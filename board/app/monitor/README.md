# okdcc monitor

NMRA DCC 信号を受信してデコードし、結果をシリアル通信に出力するテストアプリケーション。

- ボード: M5Stack Core（ESP32）
- 出力: シリアル（115200 bps）に `packet: {...}` 形式の JSON

## ハードウェア

レールの信号はフォトカプラー [TLP2361](https://akizukidenshi.com/catalog/g/g111004/)（東芝）で絶縁して GPIO 5（`DCC_SIGNAL_GPIO`）ひとつで受ける。

```
Rail A --- R1 (2.4k) -----+------ 1: Anode
                          |
                          D1 (1N4148, anode on pin 3 side)
                          |
Rail B -------------------+------ 3: Cathode

M5 3.3V --------+---------------- 6: VCC
                |
                C1 0.1uF
                |
M5 GND ---------+---------------- 4: GND

M5 GPIO 5 ----------------------- 5: VO
```

TLP2361 のピン: 1 アノード、3 カソード、4 GND、5 VO（出力）、6 VCC（2 番ピンは無い）。

### 部品

- U1: TLP2361（SO6、ピン間隔 1.27mm の表面実装品なので、ブレッドボードで使うには SOP 変換基板に載せる）
- R1: 2.4kΩ 1/2W
- D1: 1N4148 などの小信号ダイオード
- C1: 0.1µF のセラミックコンデンサー

### 注意

- **レールを M5Stack の GND に直結しないこと。**
  - DCC はレール間の極性が交互に反転する信号なので、片方を基準にするともう片方は負電圧になり GPIO を壊す。
  - 線路から整流して給電している場合、GND とレールを直結するとブリッジダイオードを短絡する。
  - USB で PC から給電している場合、PC のグラウンドを経由してブースター出力を短絡するおそれがある。
- **C1 を VCC（6 番）と GND（4 番）の間に、ピンから 1cm 以内に付けること。**
  - データシートの指定。無いと発振したり正しく ON/OFF しなかったりする。
- **D1 を LED と逆向きに並列に入れること。**
  - TLP2361 の LED の逆電圧の最大定格は 5V しかなく、レール電圧の逆極性がそのままかかると壊れる。D1 で逆電圧を約 0.7V に抑える。
- **R1 はレール電圧に合わせて選ぶこと。**
  - LED の電流は推奨 2〜6mA、最大定格 10mA。順電圧は約 1.5V。
  - R1 = 2.4kΩ のとき、レール電圧 12V で約 4.4mA、22V（NMRA の上限）で約 8.5mA になる。
  - 22V のとき R1 の消費電力は約 0.17W になるので、1/4W では余裕が無い。1/2W を使う。
- **電源は 3.3V から取ること。**
  - TLP2361 の出力はトーテムポールで、VO は VCC まで振れる。5V で動かすと GPIO に 5V がかかる。
  - トーテムポール出力なので、プルアップ抵抗は要らない。
- 出力は反転論理（LED が点くと L）になるが、両エッジの時刻を使うのでデコード結果には影響しない。
- 伝搬遅延は最大 80ns、立ち上がりと立ち下がりの遅延の差は最大 25ns で、デコーダーの許容範囲（`1` の半ビットで 52〜64µs、前後の差 6µs まで）に比べて十分小さい。
- `hardware/` の KiCad 回路図はまだフォトカプラー方式に更新していない。

## ビルドと書き込み

`board/` で次を実行する。

```sh
make build.app.monitor
make upload.app.monitor PORT=/dev/ttyUSB0
```
